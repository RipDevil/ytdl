# Инструкции для работы с репозиторием

## Назначение и ограничения

Это минимальный сервис скачивания отдельных видео с YouTube: Svelte на клиенте, Fastify на сервере, yt-dlp через `youtube-dl-exec`, запуск через Docker Compose. Используйте только JavaScript, без TypeScript.

- Работайте только внутри этого репозитория. Не создавайте, не изменяйте и не удаляйте файлы за его пределами.
- Не выполняйте коммиты и не отправляйте изменения в удалённые репозитории без явного нового указания пользователя.
- `README.md` и `AGENTS.md` должны оставаться на русском языке. Язык общения определяется указаниями пользователя.
- Сохраняйте существующий `LICENSE`.

## Архитектура

- `server/urls.js` проверяет и нормализует ссылки на отдельные видео. Параметры плейлиста удаляются.
- `server/store.js` читает и атомарно сохраняет `data/queue.json`. Не затирайте повреждённое состояние автоматически.
- `server/queue.js` управляет FIFO-очередью. Одновременно допускается только одно активное скачивание. Принимаемое задание должно быть записано на диск до успешного ответа API.
- `server/downloader.js` вызывает yt-dlp без shell, разбирает помеченные строки прогресса и останавливает процесс при отмене. Не передавайте пользовательские аргументы командной строки загрузчику.
- `server/app.js` создаёт Fastify без открытия порта; `server/index.js` отвечает за запуск и остановку.
- `web/` содержит Svelte-интерфейс. Сохраняйте простую структуру и палитру на основе `tomato`.

Хранилище рассчитано на один процесс. Не добавляйте Redis, базу данных, дополнительные сервисы или авторизацию без необходимости и согласования требований.

## Установка и проверки

```sh
YOUTUBE_DL_SKIP_DOWNLOAD=true npm ci
npm test
```

Файл `.npmrc` направляет кеш npm в `.cache/npm/` внутри репозитория. Не запускайте глобальную установку пакетов. При изменении зависимостей обновляйте `package-lock.json` с установленной переменной `YOUTUBE_DL_SKIP_DOWNLOAD=true`.

В рамках текущей задачи разрешены только серверные юнит-тесты. Не проверяйте настоящие скачивания, не запускайте Docker и не тестируйте веб-интерфейс. Не запускайте сборку или браузерные проверки как дополнительную валидацию без нового указания пользователя.

- Используйте `node:test` и `Fastify.inject`; HTTP-порт для тестов не нужен.
- Подменяйте загрузчик и дочерний процесс. Не обращайтесь к YouTube из тестов.
- Создавайте временные данные только в `.tmp/` внутри репозитория, не используйте системный временный каталог.
- Очищайте только временные каталоги, созданные конкретным тестом.
- Проверяйте существенное поведение: FIFO, единственный активный загрузчик, ошибки, сохранение, перезапуск и отмену.

## Документация и эксплуатация

При изменении API, переменных окружения или Docker Compose обновляйте `README.md`. Видео сохраняются в `/downloads`, очередь — в `/data`; оба каталога подключаются с хоста. Сервис предназначен для доверенной сети и не раздаёт скачанные файлы через HTTP. Не включайте пользовательские видео, состояние очереди, кеши, временные файлы или секреты в Git и Docker-образ.
