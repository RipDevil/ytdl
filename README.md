# Tomato

Простой сервер для скачивания видео с YouTube. Вставьте ссылку в веб-интерфейс: сервер сохранит задание в очередь и скачает видео, когда дойдёт его очередь. Одновременно обрабатывается только одно задание.

Интерфейс написан на Svelte, сервер — на Fastify и Node.js. Весь код приложения — JavaScript без TypeScript. Для скачивания используется `yt-dlp` через пакет `youtube-dl-exec`, для объединения видео и звука — FFmpeg.

## Возможности

- Минимальный интерфейс с акцентами цвета `tomato` и обновлением очереди каждые две секунды.
- Поддержка обычных ссылок YouTube, `youtu.be`, Shorts и ссылок на отдельные трансляции. У ссылки на видео удаляются параметры плейлиста; сами плейлисты не поддерживаются.
- Лучшее доступное качество видео и звука. Итоговое расширение файла определяется исходными потоками и FFmpeg.
- Сохранение видео в каталог, указанный в Docker Compose.
- Сохранение очереди и истории на диске. После перезапуска прерванное задание возвращается в очередь перед более поздними заданиями; частично скачанные файлы используются повторно, если это поддерживается источником.
- Ошибка одного задания не останавливает остальные. Для повторной попытки добавьте ссылку ещё раз.

Сервис предназначен для локальной или доверенной сети: встроенной авторизации нет. Готовые файлы открываются через каталог на хосте, а не через веб-интерфейс. Работайте с одним экземпляром сервера на каталог состояния.

## Запуск через Docker Compose

Нужны Docker и Docker Compose.

```sh
mkdir -p downloads data
docker compose up --build -d
```

Откройте **http://localhost:3000**. Видео появятся в `./downloads`, очередь и история — в `./data/queue.json`.

В `compose.yaml` задаются каталоги на хосте:

```yaml
volumes:
  - ./downloads:/downloads
  - ./data:/data
```

Замените левую часть первой записи на нужный каталог. Правая часть `/downloads` остаётся прежней. Каталог `/data` тоже должен сохраняться между пересозданиями контейнера.

Контейнер работает без прав root. По умолчанию используются UID/GID `1000:1000`. Если на Linux ваш пользователь имеет другие идентификаторы, запустите:

```sh
mkdir -p downloads data
LOCAL_UID=$(id -u) LOCAL_GID=$(id -g) docker compose up --build -d
```

У выбранного пользователя должны быть права на запись в оба каталога. Для постоянной настройки можно записать `LOCAL_UID` и `LOCAL_GID` в локальный файл `.env` рядом с `compose.yaml`.

Просмотр журналов и остановка:

```sh
docker compose logs -f
docker compose down
```

Остановка сохраняет очередь и файлы в подключённых каталогах. Не удаляйте `.part`-файлы, если хотите продолжить незавершённое скачивание.

Чтобы обновить yt-dlp и его зависимости, пересоберите образ без кеша:

```sh
docker compose build --no-cache
docker compose up -d
```

Доступность видео зависит от YouTube, сети, региона и ограничений конкретного ролика. Вход в аккаунт YouTube и импорт cookies в этой версии не предусмотрены. Активная трансляция может скачиваться до её завершения и занимать очередь всё это время.

## Локальная разработка

Нужен Node.js **22.12+**; в Docker используется Node.js 24. Для настоящего скачивания дополнительно нужны Python, актуальный yt-dlp с JavaScript-компонентами и FFmpeg. Укажите путь к yt-dlp через `YT_DLP_PATH`, если он не находится в `PATH`.

Установите зависимости без автоматического скачивания бинарного файла yt-dlp:

```sh
YOUTUBE_DL_SKIP_DOWNLOAD=true npm ci
npm run dev
```

Vite выведет адрес интерфейса, обычно `http://localhost:5173`. Запросы `/api` проксируются на Fastify, работающий на порту `3000`.

Сборка и запуск готового приложения:

```sh
npm run build
npm start
```

В этом режиме Fastify раздаёт собранный интерфейс из `dist/` на том же порту, что и API. Запускайте команды из корня репозитория.

### Переменные окружения

| Переменная | Локально по умолчанию | В Docker | Назначение |
| --- | --- | --- | --- |
| `PORT` | `3000` | `3000` | Порт HTTP-сервера |
| `DOWNLOADS_DIR` | `./downloads` | `/downloads` | Каталог видео и частичных файлов |
| `DATA_DIR` | `./data` | `/data` | Каталог файла очереди |
| `YT_DLP_PATH` | `yt-dlp` | `/opt/yt-dlp/bin/yt-dlp` | Путь к исполняемому yt-dlp |
| `NODE_ENV` | не задана | `production` | Значение `development` отключает раздачу `dist/` |

Порт API в настройках прокси Vite — `3000`. При изменении `PORT` для разработки поменяйте соответствующий адрес в `vite.config.js`. Обычный запуск Node.js не загружает `.env` автоматически; экспортируйте переменные в оболочке. Docker Compose использует `.env` для подстановки UID/GID.

## API

### `POST /api/jobs`

Тело запроса:

```json
{ "url": "https://www.youtube.com/watch?v=abcdefghijk" }
```

Ответ `201` содержит `{ "job": { ... } }`. Задание принимается только после записи на диск. Неверный запрос возвращает `400`, недоступное хранилище — `503`.

### `GET /api/jobs`

Возвращает `{ "jobs": [...], "queueError": null }`. Статусы заданий: `queued`, `downloading`, `completed`, `failed`. В записи доступны заголовок, прогресс, имя сохранённого файла, ошибка и временные отметки. Имя файла задаётся относительно каталога загрузок. Процент относится к текущему потоку: при переходе от видео к звуку он может начаться заново.

### `GET /api/health`

Возвращает `200` и `{ "status": "ok" }`. Если обработчик остановился из-за ошибки сохранения состояния, возвращается `503`. Восстановите доступ к хранилищу и перезапустите сервис. Проверка не обращается к YouTube и не запускает скачивание.

Состояние записывается в JSON через временный файл и атомарное переименование. Если файл очереди повреждён, сервер отказывается запускаться, чтобы не затереть историю. Восстановите его из резервной копии. Готовые видео остаются отдельно в каталоге загрузок.

## Юнит-тесты

```sh
YOUTUBE_DL_SKIP_DOWNLOAD=true npm ci
npm test
```

Используется встроенный модуль `node:test`. Проверяются нормализация ссылок, API через `Fastify.inject`, последовательность обработки, сохранение и восстановление состояния, ошибки диска, разбор вывода yt-dlp и отмена процесса. Загрузчик подменяется; тесты не скачивают видео, не открывают HTTP-порт, не запускают Docker и не проверяют веб-интерфейс.

Временные тестовые файлы находятся только в `.tmp/` внутри репозитория, кеш npm — в `.cache/npm/`. Тесты очищают только созданные ими временные каталоги.

## Структура

- `server/` — Fastify, очередь, JSON-хранилище и адаптер загрузчика.
- `web/` — Svelte и CSS.
- `test/` — серверные юнит-тесты с подменённым загрузчиком.
- `Dockerfile`, `compose.yaml` — контейнер и подключение каталогов хоста.
